# 风格模型后复权账本重建设计

## 目标

修复模型有效性页面的组合账本，使风格组合使用与 `ZXW策略技术因子生成.py` 一致的后复权行情，在因子全部生成、保存完成后自动更新。模型有效性改为无本金、无现金、无股数约束的等权收益指数；删除现有错误账本，从 2016 年起重新计算。

本次不修改任何风格因子的评分定义、选股方向、换仓频率、股票池门槛、20% 选取比例、200 只上限或等权规则；模型有效性指数不考虑手续费。

## 模块边界

新增一个风格账本专用 Python 模块，放在 `backtrader/models/style_portfolio_monitor/` 下。该模块负责：

- 加载与因子生成器同源的后复权日线。
- 在因子生成结束后运行组合账本更新。
- 校验复权覆盖、权重和、持仓上限和账本日期。
- 提供删除旧账本并从 2016 年全量重算的入口。

`ZXW因子/ZXW策略技术因子生成.py` 只在所有普通因子和派生因子保存完成后 `import` 该模块并调用公开入口，不复制组合实现，不直接操作 DuckDB 表，不在因子批次内执行策略。这样避免因子生成与组合账本互相污染。

## 数据流

1. 因子生成器完成行情读取、后复权、普通因子计算和保存。
2. 因子生成器完成动量、价值、成长、低波、流动性等派生评分并保存。
3. 最终钩子导入专用账本模块。
4. 专用模块读取 `signal_daily` 中已落盘的风格评分。
5. 专用模块读取 `stock_basic_data_daily` 原始行情，并应用与因子生成器相同的 `adj_factor_daily` 后复权因子。
6. 如果 `adj_factor_daily` 快路径不可用，允许回退至现有 `wide_xdy` 后复权实现；不得回退到未复权收盘价。
7. 专用模块按模型定义生成高分腿、低分腿和每日净值。
8. 结果写入 `style_monitor.duckdb`，页面继续通过现有 API 读取。

组合模块从持久化数据重新读取后复权价格，而不依赖因子生成器某个临时内存矩阵。原因是生成器会按代码和时间窗口分批计算并释放矩阵，单个批次不保证拥有完整股票截面。

## 后复权价格契约

- 股票筛选的真实交易日、成交量和成交额继续来自未复权日线。
- 因子排序读取已经落盘的风格评分。
- 组合收益统一使用后复权收盘价的日收益率。
- 同一天、同一股票不得在未复权和后复权价格之间混用。
- 快路径与回退路径必须对抽样股票、抽样日期产生一致的后复权收盘价。
- 任一请求日无法获得后复权价格时，保留现有停牌旧价语义；但数据源存在真实行情而复权数据缺失时必须报错，不能把缺失复权因子当作 1。

后复权价格用于理论模型有效性比较。页面继续明确显示这是理论监控，不把指数结果解释为可直接复制的真实账户收益。

## 无本金等权收益指数

模型有效性不再维护现金、股数、成交价、佣金或100股整数手。每次换仓只生成目标权重：

```text
目标权重 = 1 / 当日入选股票数量
```

T 日收盘计算评分并确定下一期目标组合，T+1 交易日开始持有。每日组合收益为上一交易日生效权重对应股票后复权收益率的等权平均：

```text
组合收益率(T+1) = Σ[权重(T) × 个股后复权收益率(T+1)]
指数净值(T+1) = 指数净值(T) × (1 + 组合收益率(T+1))
```

高分腿和低分腿均从100开始。指数不扣手续费，不模拟现金拖累，不模拟100股整数手，不因资金规模改变结果。停牌股票在没有新价格时沿用最后有效后复权价格，对应当日收益为0；如果股票从行情中永久消失，则按最后可用价格终止其权重，并在数据诊断中记录。

组合换仓时直接替换目标权重，不存在旧仓无法卖出的状态；选中股票数超过200只或有效股票数不足时仍按既有模型规则报错或暂停。

## 换仓修复

换仓日只保存目标代码、目标权重和评分快照。T 日评分不得参与 T 日收益，目标权重从 T+1 的第一条有效行情开始生效。换仓完成后执行以下校验：

- 目标列表不得超过200只。
- 每个生效日目标权重之和为1，允许浮点误差。
- 高分腿和低分腿的目标代码集合分别与评分排序结果一致。
- 不存在旧仓残留、现金不足、股数不足或手续费字段。

## 账本重建

修复代码和测试通过后，直接删除：

```text
D:\database\style_portfolio_monitor\style_monitor.duckdb
```

删除前验证解析后的绝对路径严格等于上述目标，不删除目录或其他文件。账本删除后，通过专用模块从 `2016-01-01` 开始全量生成所有已注册风格模型，直到行情与对应因子的共同最新日期。

重建完成后校验：

- 所有模型都具有高分腿和低分腿。
- 每个模型最新日期等于其行情与因子的共同最新日期。
- 每个生效日有效权重之和为1。
- 权重代码集合与评分选股结果一致。
- 指数计算不包含现金、股数或手续费字段。
- 账本不存在重复的模型、腿、日期主键。

## 页面与基准

模型有效性页面增加同截止日基准曲线。基准使用本地指数日线，不参与模型交易：

- 优先显示沪深300；本地不存在时显示上证指数和深证成指中可用者。
- 基准与模型曲线使用相同起止日期并在可见区间首日归一到 100。
- 页面显示每条腿的持仓数、有效行情覆盖率和最近换仓日期。
- 目标股票数超过200只、权重和不为1或行情覆盖不足时显示明确告警。

## 自动调用与失败边界

因子生成器只在全部保存阶段成功完成后调用专用模块。账本更新失败时：

- 不回滚已经正确保存的因子。
- 命令以失败状态结束并输出中文错误，避免用户误以为账本已同步。
- 不写入不完整的单日账本。
- 已成功写入的历史日期保持事务一致。

如果没有风格因子更新，专用模块检查共同最新日期；账本已追平时快速退出，不重复计算。

## 测试与验收

测试必须先复现以下错误，再实施修复：

- T日评分错误参与T日收益。
- 权重和不为1或权重代码与评分排序不一致。
- 换仓后持仓数长期超过 200 只。
- 未复权除权跳空被错误计为组合亏损。
- 现金、股数或手续费字段影响模型收益。
- 因子生成最终钩子在派生评分保存前运行。
- 基准和模型使用不同日期范围。

验收包括单元测试、服务集成测试、API 测试、前端数据契约测试和真实数据全量重建检查。修改的 Python、JavaScript、HTML 和 JSON 文件统一保持 UTF-8；中文输出不得出现乱码。

## 非目标

- 不修改任何风格评分公式。
- 不修改高分腿、低分腿的业务含义。
- 不将组合逻辑写入因子计算批次。
- 不保留或迁移旧错误账本。
- 不把网页理论组合改造成实盘下单系统。
