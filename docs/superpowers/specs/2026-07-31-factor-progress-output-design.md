# ZXW 策略因子生成进度输出设计

## 目标

增强 `ZXW因子/ZXW策略技术因子生成.py` 的终端进度输出，使运行人员能够看到当前计算的因子组、包含的因子、计算和写入区间、代码数量以及真实耗时，同时不改变因子计算、增量规划和保存逻辑，不为日志增加行情查询或重复计算。

## 输出原则

- 性能优先。只使用执行计划和已有 DataFrame 元数据，不扫描因子值，不拆分共享向量化计算。
- 耗时真实。只统计已有执行边界上的批次耗时和保存任务耗时；多个因子共享一次计算时，不显示虚假的单因子计算耗时。
- 中文清晰。终端统一输出 UTF-8 中文，因子名称按固定数量换行，避免单行过长。
- 控制频率。只在计划、批次开始、批次完成、保存任务完成和整批汇总节点输出，不逐股票或逐数据行打印。

## 终端输出

### 计算计划

每个执行批次开始前显示：

- 批次序号和总批次数；
- bundle/因子组名称和范围类型；
- 本批次目标因子数量及分行后的因子名称；
- 输入代码数量；
- 计算区间，包含指标回看区间；
- 实际写入区间。

示例：

```text
[计划] 批次 1/20：macd/all_market，因子=35，代码=7369
[区间] 计算=2026-04-10 ~ 2026-07-29，写入=2026-07-01 ~ 2026-07-29
[因子 1/4] DIF、DEA、MACD柱、底背离……
```

### 计算完成

在现有 `perf_counter` 批次计时边界上显示生成因子数量和总耗时：

```text
[完成] 批次 1/20：macd/all_market，生成=35，耗时=12.36秒
```

这里的耗时是整个向量化批次的真实耗时，不拆分为单因子耗时。

### 保存进度

保存任务沿用现有线程池，不增加等待或串行化。在任务提交前保留计划区间；任务完成时输出因子名、写入区间、月份数、行数和任务耗时：

```text
[保存完成] 3/289 DIF，区间=2026-07-01 ~ 2026-07-29，月份=1，行数=152384，耗时=0.82秒
```

并行执行时，完成顺序允许与提交顺序不同。

### 整批汇总

计算阶段和保存阶段分别显示总计。汇总值直接累计已有任务结果，不读取落盘文件：

```text
[计算汇总] 批次=20，生成因子=289，耗时=123.45秒
[保存汇总] 任务=289，月份=289，行数=44000000，耗时=31.20秒
```

## 代码结构

在主脚本内新增小型纯格式化函数，负责：

- 将因子名称按每行固定数量分组；
- 格式化日期区间；
- 输出计算计划；
- 输出计算完成信息。

保持函数位于主脚本，不创建共享文件。该输出只服务当前脚本，没有跨模块复用需求，符合现有代码组织方式。

保存任务返回值增加任务耗时和区间信息，调用方只负责打印，不改变任务调度、写入内容和异常重试行为。

## 异常处理

- 计算批次失败时不打印“完成”，异常保持原样向上传递。
- 保存任务失败时沿用现有警告和顺序重试；重试成功后显示重试耗时。
- 没有待计算或待保存任务时保留现有跳过提示，不输出误导性的耗时。

## 测试

- 测试因子名称按固定数量分行，中文内容保持不变。
- 测试计算计划包含批次、范围、因子数、代码数及两个日期区间。
- 测试完成输出包含生成数量和两位小数耗时。
- 测试保存任务返回真实的任务区间和非负耗时。
- 运行现有增量计划及整批水位相关测试，确认业务逻辑没有变化。

## 非目标

- 不统计单个因子的独立计算耗时。
- 不新增日志文件或数据库写入。
- 不增加逐股票进度。
- 不调整 bundle 分组、计算顺序、并行度或因子算法。
