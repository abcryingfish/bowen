# 形态蜡烛信号中文展示设计

## 目标

在“形态面”主看板和“量化因子有效性检验”页面中，将蜡烛形态名称统一显示为中文。中文命名参考现有形态算法注释和通用蜡烛形态术语。

## 范围

- 形态面主看板的图上标签、提示文案及形态名称使用中文。
- 量化因子有效性检验的形态因子选择项、任务标题及结果中的形态名称使用中文。
- `level1`、`level2`、`level3` 分别显示为“一级形态”“二级形态”“三级形态”。
- 所有新增和修改的文本文件继续使用 UTF-8 编码，JSON 写出时保留中文字符。

## 兼容策略

- 保留英文 `signal_name` 作为稳定技术键，例如 `engulfing_bullish`。
- 不修改形态算法、不修改信号强度、不修改方向和 K 线跨度。
- 不重命名 `factor=*` 分区目录，不迁移或重写历史 parquet。
- 在 `morph_candlestick_meta.py` 维护英文技术键到中文显示名的映射。
- 生成 manifest 时为每个形态增加 `display_name`；现有字段保持不变。
- 后端查询、过滤和去重继续使用英文键；API 额外返回中文显示名。
- 前端优先显示 API/manifest 提供的中文名；缺失映射时回退英文键，避免旧 manifest 导致页面不可用。

## 命名规则

- 有明确多空方向的形态使用“看涨/看跌”前缀，例如“看涨吞没”“看跌吞没”。
- 已有固定中文术语的形态沿用固定名称，例如“乌云盖顶”“刺透形态”“早晨之星”“黄昏之星”“金针探底”。
- 同一英文技术键在两个页面必须显示相同中文名。
- 中文显示名必须唯一，避免有效性检验页面出现无法区分的选项。

## 数据流

1. 形态元数据模块根据英文技术键生成包含 `display_name` 的 manifest。
2. 形态信号生成脚本继续写入英文 `signal_name`，同时刷新 manifest。
3. `market_data_service.py` 在形态 API 响应中附带中文显示名。
4. `factor_validation_service.py` 在因子列表和任务结果中保留英文因子标识，并提供中文标签。
5. 两个前端只替换展示文本，不改变请求参数和内部状态键。

## 错误处理

- manifest 不存在、格式异常或某个形态缺少中文映射时，页面回退显示英文技术键。
- 未识别的英文信号仍可查询和绘制，不因中文映射缺失而丢弃。
- 中文名称不得参与 parquet 路径拼接、SQL 过滤或去重键生成。

## 验证

- 单元测试覆盖 manifest 中 `display_name` 的生成、UTF-8 JSON 往返和未知键回退。
- 服务测试覆盖形态列表与事件响应同时包含稳定英文键和中文标签。
- 前端测试覆盖有效性检验页与形态面主看板均优先显示中文名称。
- 运行现有形态信号生成、有效性检验和市场数据相关测试，确认查询逻辑未回归。
- 浏览器检查两个页面，确认中文无乱码、标签不溢出且相同形态命名一致。
