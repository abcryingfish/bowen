# 同花顺客户端板块分钟数据补全设计

## 目标与边界

从本机普通同花顺客户端获取数据库现有全部 `.THS` 板块自 2010-01-01 起的 1 分钟数据，写入 `D:\database\index_data_mins`。数据源只能是客户端原生“分钟 K 线数据下载”、客户端“数据导出”及其本地缓存；禁止使用 Fuyao、iFinD、网页行情接口和其他行情供应商。

新成立或改版板块从客户端实际首个日线交易日起计算完整性。任务只有在全部应有交易日和分钟序列通过检查后才视为完成。

## 获取架构

目标代码以数据库现有 `.THS` 清单为准，客户端 `Market_48` 名称表只用于校验代码、名称和当前可用状态，不自动扩大标的范围。下载按小批次执行，初始粒度为代码批次加年份；客户端异常或数据缺失时依次缩小为单代码加月份、单代码加交易日。

每个批次依次执行：打开客户端数据下载中心、选择“分钟 K 线数据”、设置市场和日期范围、等待下载结束、打开客户端数据导出、选择“同花顺指数2期”和“1分钟”、导出到独立临时目录、解析并校验导出结果。实测 9.60.20 客户端下载中心对分钟数据提示只能保持近 3 个月，且历史日期导出会返回“导出数据失败或者没有数据可导出”；因此 3 个月以前的窗口必须走历史分时回放/本地 `hisminutei.trd` 解码路径，不能把下载中心的空结果记为成功。窗口句柄每次动态查找，使用窗口相对坐标和 Win32 消息，避免全局鼠标坐标导致误触退出。

任务状态保存到 `D:\database\index_data_mins\_meta`，记录代码、时间窗口、尝试次数、客户端状态、导出文件和错误原因。进程或客户端重启后从未完成窗口继续。

## 数据转换与落盘

客户端导出文本自动识别 UTF-8、UTF-8 BOM、GBK 和 GB18030。代码统一为 `xxxxxx.THS`，时间使用无时区的北京时间。输出保持现有分钟库字段：`htsc_code`、`time`、OHLC、`volume`、`amount`、`date`、`pre_close`、`change`、`pct_chg` 和 `__index_level_0__`。

以 `htsc_code + time` 去重并保留最后一条。数据先写临时文件，重新读取校验成功后再原子替换正式 `merged.parquet`；异常时保留旧分区。只重建实际触及的日分区，不改股票分钟数据业务逻辑。

## 完整性检查

同花顺客户端导出的板块日线定义该代码的有效交易日。对每个有效交易日检查：存在分钟数据、时间严格递增、没有重复、开盘和收盘边界存在、午间边界合理、分钟网格没有断点。241/242 根不硬编码，按客户端同一时期的实际时间网格判断。

同时检查 OHLC 有限且满足 `high >= max(open, close)`、`low <= min(open, close)`，成交量和成交额非负，关键字段无空值。缺失报告按代码、月份、交易日输出 CSV 和 JSON。

## 重试与终止

首次失败后缩小请求范围；仍失败时重启 `HxDataService` 或同花顺客户端，再重试单日窗口。每轮完成后重新扫描正式数据库，只保留仍然缺失的窗口。没有固定重试次数会把缺失窗口误报为完成；持续失败会记录原因并继续留在待办队列。

终止条件为目标清单全部代码的应有交易日缺失数为零、分钟断点数为零、重复键数为零和数据质量异常数为零。最终报告包含代码数量、每个代码实际起止日、行数、重试次数和所有校验计数。

## 安全与可观测性

脚本不读取或记录账号密码，不访问任何外部行情 URL。客户端未登录、窗口不可用、导出超时、磁盘不足或 Parquet 被占用时，不覆盖正式数据，并留下可续跑状态。

运行前后检查 `D:\CodexHome\logs_2.sqlite` 的 `block_trace_logs_insert` trigger、TRACE 行数和 WAL 大小，确认 TRACE 不再高频增长。日志和报告使用 UTF-8；需要给 Excel 查看时使用 UTF-8 BOM。

## 验证

单元测试覆盖客户端代码表解析、导出文件编码和字段解析、日期/分钟完整性、去重、原子写入、状态恢复及禁止外部 URL。集成冒烟测试先使用 `881102.THS` 的已知缺口，确认 `2018-08`、`2019-01` 至 `2019-05` 以及 `2018-07`、`2018-09` 的残缺交易日能够进入补取队列。批量运行后再次全库扫描，只有最终验收指标全部为零才返回成功。
