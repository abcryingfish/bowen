# 模型有效性页面设计

## 目标

新增一个名为“模型有效性”的独立可视化页面，用于后续研究不同风格因子的实时有效性。当前阶段只搭建页面结构和六个图表窗口，不绑定真实因子、评分逻辑或交易建议。

## 入口与导航

- 页面目录：`可视化/模型有效性/`。
- 入口：复用现有 `edge-float-hud` 悬浮球菜单。
- 在 `可视化/shared/edge_float_nav.js` 的统一页面注册表中新增 `model-validity` 页面项。
- 页面自身继续加载共享悬浮球脚本，使用户可以返回其他页面。
- 不新增顶部主导航项，不修改已有页面的业务逻辑。

## 页面布局

- 页面使用 UTF-8、中文标题“模型有效性”。
- 主区域为 3×2 网格，共六个独立图表窗口。
- 六个窗口先使用中性标题：风格图 1 至风格图 6，避免在因子尚未定义前产生业务假设。
- 每个窗口保留 TradingView 风格的深色绘图区、时间轴、当前时间点标记和简短占位说明。
- 页面可在窄屏下自动变为两列或单列，确保图表不被裁切。

## 数据与交互

- 第一版使用前端确定性演示数据，仅用于验证页面布局和图表渲染。
- 数据通过独立适配器提供，后续可替换为真实 API，不改变卡片结构。
- 暂不加入因子选择、有效性分数、买卖建议、回测按钮或复杂筛选。
- 预留“刷新”与“当前点”视觉位置，但不要求接入实时行情。

## 实现边界

- 新增页面 HTML、页面专属 CSS 和页面专属 JS；共享脚本只做导航注册所需的最小修改。
- 优先复用现有 `edge_float.css`、`edge_float_nav.js`、`edge_float_hud.js` 与万花筒画布脚本。
- 不移动或复制旧页面业务代码，不修改现有因子检验、行情或回测逻辑。
- 所有中文文件保存为 UTF-8，避免路径和页面文案乱码。

## 验证

1. 静态检查新页面 HTML、CSS、JS 文件可读取且无明显语法错误。
2. 启动现有静态 Web 服务后，访问 `模型有效性/index.html`，确认中文标题和 6 个图表窗口正常显示。
3. 从其他页面打开 `edge-float-hud`，确认菜单出现“模型有效性”；点击后可进入新页面。
4. 在新页面打开悬浮球，确认可以返回其他已注册页面。
5. 在窄窗口下确认图表网格会自适应，不出现横向溢出。
