# 普通与两融账户跨周期委托状态机设计

## 目标

将普通账户和两融账户的盘口追单从阻塞式循环改为跨定时周期状态机。每次定时回调只查询一次行情和委托状态，不使用 `sleep` 等待，不因单个账户的撤单确认拖慢另一个账户。

两份脚本分别实现，不共享业务文件。普通账户继续使用普通买卖方向和普通撤单接口；两融账户继续使用融资买入、卖券还款及信用账户撤单接口。

## 状态流

1. `ready_to_submit`：重新读取买一/卖一价格和数量，检查滑点、涨跌停、交易时间、最大轮数以及可用持仓，然后提交本轮委托。
2. `waiting_fill_ticks`：按有效行情 tick 计数。未满 2 tick 时只对账成交量，不撤单、不补单。
3. `cancel_requested`：2 tick 后仍未全部成交时，每个 `order_id` 只提交一次撤单。
4. `waiting_terminal`：已报、部成、待撤等非终态持续等待。即使超过 2 tick，也绝不提交下一笔。
5. `ready_to_retry`：旧委托进入已成、已撤、废单或拒绝等终态后，核算最终累计成交量，再进入下一轮重新报价。
6. `completed/stopped`：目标完成，或因最大轮数、滑点、涨跌停、收盘等保护条件停止。

## 成交量核算

- 柜台 `order_id` 返回累计成交量。
- 每次新增成交量为 `max(本次累计成交量 - 该委托已记录累计成交量, 0)`。
- 撤单在途期间可能继续成交；旧委托终态时必须再次查询并记录最终增量。
- 信号累计成交量等于其全部 `order_ids` 的最终成交量之和。
- 下一轮剩余量由原始目标扣减累计成交量，不根据上轮申报量直接推断。
- 买入金额目标按实际已确认成交金额扣减；无法取得成交金额时使用该委托成交均价，仍无法取得时才以委托限价兜底并记录日志。

## 买卖与数量规则

- 买入每轮匹配最新卖一；卖出每轮匹配最新买一。
- 每轮申报量不超过最新对手盘数量和当前剩余目标量。
- 普通追单按整百股处理。
- 全部卖出时，最后不足 100 股的零股允许一次卖出。
- 卖出每轮重新查询可用持仓，申报量不超过可用持仓。
- 半仓卖出的原始目标量首次确定后持久化，后续只扣减累计成交量，不能根据变化后的持仓再次计算一半。

## 持久化与恢复

response 每个执行中信号保存：

- 全部 `order_ids`
- 当前活动 `order_id`
- 当前阶段 `execution_stage`
- 原始目标量或金额
- 累计成交量、累计成交金额、剩余量
- 当前委托已记录累计成交量
- 已等待 tick 数、追单轮数
- 撤单提交时间和次数
- 最后更新时间和停止原因

每次阶段变化或成交增量出现后立即原子保存。程序重启后以 response 为线索，再按柜台 ORDER/DEAL 数据对账；柜台状态优先于 response。执行中信号继续占用股票代码，不能被防重逻辑当成已完成，也不能启动第二条同向委托。

## 异常与保护

- `51/52` 及文本“待撤”等状态属于非终态：只等待，不重复撤单，并持续阻塞该股票的新委托。
- 终态长期不返回时持续对账并按固定间隔告警，不以超时强行补单。
- 委托对象暂时查不到时保留原阶段，下一周期重查。
- 无法识别累计成交量时不补单，避免重复成交。
- 保留最大追单轮数、最大滑点、涨跌停、交易时间及收盘前停止追单规则。
- 收盘前停止新申报和追单，但已有非终态委托仍继续对账并按既定规则撤单。
