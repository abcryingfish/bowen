# 板块 Staging 看板预览设计

## 目标

让 `可视化/多维度分析/index.html` 的板块选择器能够查看以下研究结果：

- 正式报告：乳业 `885462.THS`
- Staging 候选：化学制药 `881140.THS`
- Staging 候选：半导体 `881121.THS`

## 数据边界

- 不复制研究 JSON。
- 不写入正式 `reports`、`current` 或共享知识库。
- 后端只读访问固定白名单中的两个 staging 目录。
- 化学制药读取 `report.json`；半导体兼容 `report_candidate.json`。
- API 返回 `_report_stage`，前端必须显示“正式”或“staging候选”。

## 接口行为

- `/api/sector/entities`：在正式实体列表后合并两个预览实体，按 `sector_code` 去重。
- `/api/sector/report`：优先读取正式报告；正式报告不存在时，仅允许读取白名单 staging 报告。
- staging 路径缺失、JSON损坏或代码不匹配时返回现有 `NOT_FOUND`/`READ_FAILED` 错误，不扫描其他 staging。

## 前端行为

- 选择器显示乳业、化学制药和半导体。
- 切换板块继续使用 `?sector=代码`，保留现有锚点布局和全展开栏目。
- 顶部元信息和徽标明确显示报告阶段，避免将候选报告误认为正式发布。
- 保持现有字段缺失降级逻辑；不使用演示数据补齐缺失栏目。

## 验证

- UTF-8 严格读取三份报告。
- API实体列表包含三个目标板块且无重复。
- 两个 staging 报告可读取，未知代码仍返回不存在。
- 浏览器分别切换三个板块，检查标题、综合分、六维评分、预测、搜索日志、证据和审计信息。
- 桌面与窄屏页面无文本重叠，控制台无错误。
