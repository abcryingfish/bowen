## 3. V2 标签的代码事实与边界

关键实现：

- `ZXW因子/peak_valley_expost_annotation_v2.py`
- `ZXW因子/generate_peak_valley_v2_labels.py`
- 设计说明：`docs/superpowers/specs/2026-08-09-peak-valley-expost-annotation-v2-design.md`

V2 输出 12 个 label-only 字段：峰/谷事后连续强度、局部位置、趋势转折、反转强度、反转持续性、确认延迟。计算使用居中窗口、未来 5/10/20/40 bars、ATR 标准化反转和 epsilon=0.02 的平滑几何均值。所有 12 个字段都含未来信息或事后诊断信息，均不得进入 `X`。

关键公式语义：

```text
strength = ( Π(component + 0.02) )^(1/4) 经过 epsilon 平滑回到 [0,1]
```

`0` 不是人工确认的负例，只是算法给出的最低强度；未标注日期不能自动当负样本。V2 最长未来窗口为 40 个交易日，所以行情尾部至少剔除 40 个交易日；时间切分之间建议 purge/embargo 40 至 60 个交易日。

## 4. 推荐建模路线

1. **数据集契约**：按 `htsc_code + time` 对齐行情、普通因子和 V2 目标，保留 `sector_family`（881/885/886）作为分组信息。
2. **因子审计**：覆盖率、缺失率、重复列、时间因果性、股票级/板块级语义、年份稳定性。
3. **监督学习基线**：ElasticNet 作为方向性基线，LightGBM/CatBoost 作为主基线，分别预测峰强度和谷强度。
4. **严格验证**：滚动时间切分，按年份、板块族、单板块报告；禁止随机拆分。
5. **序列模型**：树模型稳定后再使用最近 60 个交易日的 TCN/GRU；Transformer/TFT 延后。
6. **组合决策**：先用规则化排名、约束优化或均值方差组合器；监督预测稳定后再研究 PPO/SAC/Offline RL。

模型指标应包括 Spearman IC、Top-K 命中率、强事件 PR-AUC、分年份/分族稳定性、校准；交易指标应包括未来 5/20/40 日收益、回撤、换手、成本、Sharpe/Calmar 及相对等权板块超额。

## 5. 必须交给后续 Agent 的工程风险

### 5.1 标签分区可能重复

`generate_peak_valley_v2_labels.py::_write_batch_parts` 生成随机名 `part_v2_*.parquet` 并追加写入。若同一日期/代码再次刷新而没有先清理旧 part，DuckDB 读取会产生重复主键，训练集会被隐性加权。本次已对 12 个 V2 因子全量检查 `(factor, htsc_code, time)`，当前重复行均为 0；这是潜在写入风险，不是当前故障。后续仍应保持去重检查，并考虑原子替换或 manifest/version。

### 5.2 上下文边界不是固定交易日 bars

批处理使用 `context_start = start - 120 calendar days`，但 V2 的窗口是交易日 bars。节假日、停牌和跨年时可能不足 60 根交易日。应改为按每个代码的交易日索引取前置 bars，或至少在数据集构建阶段验证上下文长度。

### 5.3 尾部与增量刷新

V2 未来依赖会使最近约 40 根交易日的 label 不稳定；`plan_peak_valley_v2_refresh` 已提供尾部重算思路，但生产写入仍需验证旧 part 是否删除、重算是否幂等。

### 5.4 目标定义与交易目标可能不完全一致

V2 是“事后形态强度”，不是直接的未来收益目标。必须额外报告 label 与未来 5/20/40 日收益、最大有利/不利变动的关系，避免模型只学到形态分数而没有交易价值。
