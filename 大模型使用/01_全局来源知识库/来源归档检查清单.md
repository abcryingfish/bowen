# 每次研究结束的来源归档检查清单

本清单必须在正式发布前执行。任一必填项未完成，研究只能保留在 `staging`。

## 1. 访问清单

- [ ] 已列出本次实际访问的所有来源入口。
- [ ] 每个入口都有访问结果：成功、失败、重复、错配或拒绝。
- [ ] 搜索结果页和正文来源已分开记录。
- [ ] 分析日之后或发布时间不明的内容已正确排除。

## 2. 有效来源

- [ ] 新来源已生成稳定 `source_id`。
- [ ] 已记录来源类型、适用对象和支持维度。
- [ ] 已记录权威等级、日期可靠性和访问方式。
- [ ] 已设置生命周期状态和优先级。
- [ ] 已记录发现该来源的 `run_id`。

## 3. 已有来源复验

- [ ] 已更新 `last_checked_at` 和 `last_checked_by_run_id`。
- [ ] 成功时已更新成功次数和最近成功时间。
- [ ] 失败时已更新失败次数和最近失败原因。
- [ ] 来源适用范围发生变化时已更新，而不是复制新记录。
- [ ] 更权威来源出现时已调整优先级或标记 `deprecated`。

## 4. 失败与拒绝

- [ ] 可复用的失败经验已写入失败路径库。
- [ ] 已区分 `retrieval_failed`、`mismatch`、`post_date_excluded` 和重复转载。
- [ ] 已记录重试策略和替代入口。
- [ ] 北交所错配来源未进入有效证据和评分。

## 5. 对象档案

- [ ] 对目标板块或个股有长期价值的来源已写入对象 `有效来源.md`。
- [ ] 对象特有失败路径已写入对象 `失败尝试.md`。
- [ ] 全局来源与对象来源使用相同 `source_id`。

## 6. 发布门槛

- [ ] 已生成本次运行的来源归档摘要。
- [ ] `source_archive_completed=true`。
- [ ] 新增、复验、状态变化、失败、废弃和拒绝数量可复核。
- [ ] 如果没有来源变化，已记录 `no_source_registry_change=true`。
- [ ] 归档摘要已关联 `run_id`、对象代码和分析日期。
