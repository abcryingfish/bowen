# 板块峰谷机器学习每日增量推理运行手册

> 适用范围：在板块行情和普通因子已经更新后，生成最新交易日的板块涨跌状态概率。
> 本流程只更新数据和执行已训练模型推理，禁止训练、调参、重新校准或注册模型。

## 强制执行约定

以后收到“更新板块模型数据”“生成最新板块涨跌概率”“板块轮动更新到最新交易日”或类似任务时，必须先读取本文，再完整执行“日期确认 -> 上游数据刷新 -> 每日推理 -> 数据与前端验收”。不能只运行 `sector_daily_signal.py`。

- Python 固定使用项目根目录的 `.venv\Scripts\python.exe`。
- PowerShell 先设置 `$env:PYTHONIOENCODING='utf-8'`，避免中文日志乱码。
- 支持范围固定为 881、885、886；当前模型不包含 882。不得给 882 伪造、复制或插值概率。
- 同花顺板块指数使用连续 OHLC，不叠加个股复权因子。
- 成分股价格只按既有逻辑执行一次 `raw_ohlc * adj_factor_daily`，不得先读取已复权价格再乘复权因子。
- 不得运行文件名包含 `model`、`blend`、`train`、`register`、`audit` 的训练/评估入口，本文明确列出的推理依赖阶段除外。
- 每一步失败后立即停止后续阶段，先修复当前输入；不得用旧日期结果冒充最新日期。

## 为什么不能只运行每日推理

`sector_daily_signal.py` 只读取已经落盘的技术子组、因子组和已训练模型。普通因子生成完成并不代表这些板块模型输入已经更新。

2026-08-24 排查时出现过以下状态：

- `signal_daily` 和板块行情已经到 `2026-08-21`。
- `technical_subgroups_v1`、`factor_groups_v1` 和最终概率仍停在 `2026-08-17`。
- 直接指定 `--asof-date 2026-08-21` 会报 `ValueError: 没有找到指定日期数据: 2026-08-21`。

根因是板块标签没有包含最新的未完成标签行，导致部署面板、V2 目标键、18 个技术子组和 7 个因子组全部停在旧日期。每日更新必须按本文顺序逐层推进水位。

## 第一步：确定目标交易日

目标日期不是自然日，也不能直接使用今天。应取 `D:\database\index_data_daily` 中 881、885、886 板块行情的共同最新交易日，并确认该日三个前缀均有数据。以下 PowerShell 会自动取得目标日期和目标月起始日：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$TargetDate = (@'
import duckdb
row = duckdb.sql("""
SELECT CAST(time AS DATE) AS trade_date
FROM read_parquet(
    'D:/database/index_data_daily/year=*/month=*/merged.parquet',
    hive_partitioning=true,
    union_by_name=true
)
WHERE LEFT(UPPER(TRIM(CAST(htsc_code AS VARCHAR))), 3) IN ('881', '885', '886')
GROUP BY 1
HAVING COUNT(DISTINCT LEFT(UPPER(TRIM(CAST(htsc_code AS VARCHAR))), 3)) = 3
ORDER BY 1 DESC
LIMIT 1
""").fetchone()
if not row:
    raise RuntimeError('没有找到 881/885/886 的共同交易日')
print(row[0].isoformat())
'@ | .venv\Scripts\python.exe -).Trim()
$TargetMonthStart = ([datetime]$TargetDate).ToString('yyyy-MM-01')
Write-Host "目标交易日=$TargetDate，目标月起始日=$TargetMonthStart"
```

同时检查：

1. `D:\database\signal_daily\_meta\factor_batch_watermark.json` 状态为 `complete`，日期不早于目标交易日。
2. 目标日板块行情主键 `htsc_code + time` 无重复。
3. 目标日支持范围内的板块代码集合非空；记录 881、885、886 各自数量，供最终对照。

若普通因子水位落后，应先运行 `ZXW策略技术因子生成.py`。完成后重新检查水位，不要直接进入板块推理。

## 第二步：按固定顺序刷新推理输入

在项目根目录执行，沿用第一步自动得到的 `$TargetDate` 和 `$TargetMonthStart`。

```powershell
$env:PYTHONIOENCODING = 'utf-8'

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_label_stage.py" `
  --end-date $TargetDate `
  --write-start-date $TargetMonthStart `
  --write-end-date $TargetDate

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_panel_stage.py" `
  --include-incomplete

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_v2_change_target_stage.py"

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_technical_subgroup_stage.py"

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_factor_group_stage.py"

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_market_state_conditioned_stage.py"

.venv\Scripts\python.exe -u "ZXW因子\板块峰谷机器学习\sector_daily_signal.py" `
  --asof-date $TargetDate
```

阶段含义：

| 顺序 | 阶段 | 必须达到的结果 |
|---|---|---|
| 1 | `sector_label_stage.py` | 标签键覆盖目标日；最近 40 个交易日允许 `label_complete=false` |
| 2 | `sector_panel_stage.py --include-incomplete` | 部署面板覆盖目标日；未完成标签只提供推理主键，不用于训练 |
| 3 | `sector_v2_change_target_stage.py` | V2 目标文件主键覆盖目标日；最新未来目标为空是正常现象 |
| 4 | `sector_technical_subgroup_stage.py` | 18 个技术子组全部覆盖目标日 |
| 5 | `sector_factor_group_stage.py` | 六个基础因子组全部覆盖目标日 |
| 6 | `sector_market_state_conditioned_stage.py` | 第七个市场状态因子组覆盖目标日 |
| 7 | `sector_daily_signal.py` | 使用已有模型生成目标日 15 类概率和诊断文件 |

不要交换步骤。技术子组依赖 V2 目标文件的主键；市场状态组依赖前面四个基础因子组；最终推理要求所有模型输入在指定日期同时存在。

## 第三步：验收数据

最终至少检查以下项目，任何一项失败都不能宣布完成：

- `outputs/sector_peak_valley_ml/stage_ax_daily_signal/daily_signal_manifest.json`：
  - `asof_time` 等于目标交易日。
  - `training_or_tuning` 必须为 `false`。
- `sector_probability_latest_15.parquet`：
  - 最小和最大 `time` 都等于目标交易日。
  - `htsc_code + time` 重复数为 0。
  - 空值总数为 0。
  - 代码集合等于目标日行情中的 881、885、886 代码集合。
  - 超短、5日、20日各自五类概率逐行合计为 1，允许浮点误差不超过 `1e-10`。
  - 所有概率均位于 `[0, 1]`。
- `sector_signal_diagnostics_latest.parquet`：行数和代码集合与概率文件一致。
- `blend_reconstruction_error_max`：每个目标不超过 `1e-8`。
- 历史概率和诊断的当月 `merged.parquet` 最大日期等于目标交易日，且无重复主键。

当前五类状态为：

- `valley_bullish`
- `peak_bearish`
- `two_sided_high_volatility`
- `sideways_bullish`
- `sideways_bearish`

三个周期分别为 `ultra_short`、`5d`、`20d`，合计 15 个概率列。

## 第四步：验收 API 和前端

API 服务默认地址为 `http://127.0.0.1:8000`，前端默认地址为 `http://127.0.0.1:8086/板块轮动/index.html`。

逐个请求：

```text
GET /api/market/sector-model-signals?prefix=881
GET /api/market/sector-model-signals?prefix=885
GET /api/market/sector-model-signals?prefix=886
```

每个响应的 `data.latest_time` 必须等于目标交易日，`data.items` 数量必须与目标日对应前缀的行情代码数一致。前端状态栏应显示“峰谷模型已加载：目标日期，N 个板块”，板块卡片应显示同一日期的超短、5日和20日概率。

882 页面可以展示行情，但当前没有模型概率。若将来需要覆盖 882，必须单独扩展标签、特征、训练和验证范围；这属于模型变更，不属于本文每日增量流程。

## 本次遇到的问题和修复

### 1. 上游水位不同步

症状：普通因子已到 8 月 21 日，最终概率仍是 8 月 17 日。

处理：不重训模型，按标签、部署面板、V2 目标键、技术子组、基础因子组、市场状态组、每日推理的顺序刷新数据。

### 2. 标签脚本重写全部历史并遇到 Windows 文件锁

症状：标签脚本每次覆盖 2016 年以来全部年月分区，在写 `2020-09/merged.parquet` 时遇到 `os error 32`。

处理：`sector_label_stage.py` 增加 `--write-start-date` 和 `--write-end-date`，只选择日期范围涉及的整月分区，日常运行只覆盖目标月。

### 3. 直接覆盖导致 Parquet 被截断

症状：旧实现直接打开正式文件写入，发生文件锁后 `2020-09/merged.parquet` 变成损坏的小文件，DuckDB 报 `too small to be a Parquet file`。

处理：改为在同目录写唯一临时文件，完整成功后再原子替换正式文件；替换失败时删除临时文件并保留原正式文件。本次已重新生成并验证损坏分区。

### 4. 月中日期可能造成整月数据丢失

症状：如果只按 `time >= 目标日` 过滤后覆盖 `merged.parquet`，会用单日数据替换整月文件。

处理：写入边界按月份选择，命中某月时写入该月全部标签数据。即使传入月中日期，也不会丢失同月其他交易日。

### 5. 中文控制台乱码

症状：PowerShell 中阶段名称和异常路径显示乱码。

处理：运行前设置 `PYTHONIOENCODING=utf-8`；CSV 继续使用 `utf-8-sig`，JSON 和 Markdown 使用 UTF-8。

## 常见异常处理

| 异常 | 优先检查 | 处理方式 |
|---|---|---|
| `没有找到指定日期数据` | 18 个技术子组和 7 个因子组的最大日期 | 从本文第二步第一项重新按顺序执行 |
| `too small to be a Parquet file` | 报错所指年月分区大小和可读性 | 用完整历史计算、限定该整月写入边界重新生成，不要删除整个标签库 |
| `os error 32` | 文件是否被 API、Notebook 或其他 Python 进程占用 | 保留正式文件，关闭占用后重跑对应整月；不得改回直接覆盖 |
| 概率和不为 1 | 15 类概率文件、状态模型输入和列映射 | 停止发布，检查推理日志；不得手工归一化掩盖上游错误 |
| 前端仍显示旧日期 | API 返回日期、浏览器请求端口和当月历史分区 | 先确认 8000 API，再刷新页面；不要只看 CSV 修改时间 |
| 882 没有概率 | 模型支持范围 | 属于预期，不得在每日任务中扩范围 |

## 每日完成报告模板

完成后向用户报告：

1. 目标交易日、普通因子水位和最终概率水位。
2. 881、885、886 各自数量和合计数量。
3. 重复键、空值、概率和误差、诊断重构误差。
4. API 与前端实际读取日期。
5. 明确说明本次没有训练模型、没有修改模型文件、没有重复复权。
6. 本次发现的异常、修复方式和是否影响历史分区。
